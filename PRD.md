# Итоговое задание: Многопользовательский табличный процессор на React и TypeScript

## Обзор проекта

В рамках задания разрабатывается только фронтенд сервиса. Логику выдачи и проверки токенов, работы с базой данных реализовывать не нужно.

Корректная работа механизма аутентификации и авторизации, сохранения/загрузки документов демонстрируется созданием тестов с заглушками, имитирующими сервер.

## Цель

Разработать многопользовательское веб-приложение типа «табличный процессор» (spreadsheet).

Каждый зарегистрированный пользователь работает только со своими документами — чужие документы недоступны.

Приложение поддерживает создание, редактирование и удаление личных таблиц с богатой функциональностью ячеек.

---

# 1. Базовый табличный процессор (UI + логика ячеек)

## Цель

Реализовать интерактивную таблицу с возможностью редактирования ячеек, базовыми формулами и управлением структурой (строки/столбцы).

## Функциональные требования

- [x] Рендеринг таблицы размером `N×M`
  - по умолчанию: `26` столбцов × `100` строк
  - заголовки столбцов: `A–Z`
  - строки: `1–100`

- [x] Выбор ячейки по клику
- [x] Выделение диапазона с зажатым `Shift`
- [x] Редактирование ячейки:
  - двойной клик
  - нажатие `Enter`
  - инлайн-редактор

- [x] Поддержка типов данных:
  - строка
  - число
  - логическое значение
  - формула (`=`)

- [x] Базовые формулы:
  - `=SUM(A1:A5)`
  - `=AVERAGE(B1:B3)`
  - `=A1+B1`
  - `=A1*2`

- Панель формул над таблицей:
  - показывает содержимое активной ячейки

- Добавление/удаление строк и столбцов:
  - через контекстное меню (ПКМ)

- Изменение:
  - ширины столбца
  - высоты строки
  - через перетаскивание

## Критерии приёма

- Клик на ячейку — выделение
- Двойной клик — режим редактирования
- Ввод `=SUM(A1:A3)` вычисляет и отображает результат
- Добавление строки через контекстное меню вставляет строку без полной перерисовки таблицы
- Таблица из `1000` строк рендерится без видимых задержек (виртуализация)
- Ширина столбцов меняется перетаскиванием

# 2. Управление личными документами и сохранение

## Цель

Реализовать полноценный CRUD для личных документов пользователя:

- создание
- переименование
- удаление
- автосохранение
- экспорт данных

## Функциональные требования

### Управление документами

- Дашборд со списком документов текущего пользователя:
  - название
  - дата создания
  - дата последнего изменения
  - превью (первые `3×3` ячейки)

- Создание нового документа:
  - модальное окно
  - поля:
    - «Название»
    - «Начальный размер» (`строки × столбцы`)

- Переименование документа:
  - инлайн
  - или через кнопку

- Удаление документа с подтверждением
- Дублирование документа

### Сохранение и синхронизация

- Автосохранение:
  - изменения дебаунсятся (`500 мс`)
  - PATCH `/documents/:id`

- Индикатор статуса:
  - «Сохранено»
  - «Сохранение...»
  - «Ошибка сохранения»

- Ручное сохранение:
  - `Ctrl + S`

- Предупреждение при закрытии вкладки:
  - `beforeunload`

### Экспорт и импорт

- Экспорт таблицы в CSV
- Экспорт в JSON
- Импорт CSV с отображением названий колонок

## Критерии приёма

- Пользователь видит только свои документы
- Изменение ячейки автоматически сохраняется в течение `500 мс`
- CSV корректно открывается в Excel / Google Sheets
- Импорт CSV из `500` строк не вызывает зависаний
- Создание, переименование, дублирование и удаление документов работают корректно

# 3. Внедрение Redux Toolkit

## Цель

Перенести всё глобальное состояние приложения из локальных:

- `useState`
- `useReducer`
- `Context`

в Redux Toolkit.

Рефакторинг не должен ломать существующую функциональность.

## Требования

### Архитектурные изменения

- Установка и настройка:
  - `@reduxjs/toolkit`
  - `react-redux`

- Типизация:
  - `RootState`
  - `AppDispatch`

- Экспорт хуков:
  - `useAppSelector`
  - `useAppDispatch`

### Разделение store на slices

#### `spreadsheetSlice`

- ячейки
- выделение
- история изменений (`Undo/Redo`)

#### `documentsSlice`

- список документов
- статус загрузки
- активный документ

#### `uiSlice`

- модальные окна
- уведомления
- статус сохранения

#### `authSlice`

Подготовить структуру заранее, временно хранить mock-пользователя до недели 5.

### Дополнительные требования

- Реализация `Undo/Redo` через `spreadsheetSlice`
- `createAsyncThunk` для:
  - загрузки списка документов
  - загрузки документа
  - сохранения

- Автосохранение:
  - middleware
  - debounce

## Требования к рефакторингу

- Все глобальные данные, кроме локального UI конкретной ячейки, хранятся в Redux
- Слайсы покрыты unit-тестами
- Новая функциональность не добавляется

## Критерии приёма

- Глобальное состояние находится в Redux Store
- В Redux DevTools отображаются основные действия
- `Ctrl + Z` отменяет последнее изменение
- `Ctrl + Y` повторяет отменённое изменение
- Существующие функции работают без регрессий
- Reducers покрыты unit-тестами

# 4. Внедрение React Router

## Цель

Внедрить клиентскую маршрутизацию с помощью React Router, организовать структуру страниц и подготовить маршруты к подключению авторизации.

## Требования

### Архитектурные изменения

- Установка `react-router-dom`

### Структура маршрутов

| Маршрут                  | Компонент               | Доступ    |
| ------------------------ | ----------------------- | --------- |
| `/`                      | Redirect → `/dashboard` | Публичный |
| `/dashboard`             | `DashboardPage`         | mock-auth |
| `/documents/:documentId` | `SpreadsheetPage`       | mock-auth |
| `/profile`               | `ProfilePage`           | mock-auth |
| `*`                      | `NotFoundPage`          | Публичный |

### Дополнительные требования

- Layout-маршруты:
  - `AppLayout`
  - шапка + боковая панель

- Использование:
  - `useNavigate`
  - `useParams`
  - `useLocation`

- Передача `documentId` из URL в `documentService`
- Подготовка `ProtectedRoute`

### Навигационные паттерны

- Хлебные крошки:
  - `Мои документы → [Название документа]`

- Подтверждение перехода при несохранённых изменениях:
  - `useBlocker`

- Обработка `404`

## Критерии приёма

- Прямая ссылка `/documents/abc123` открывает документ
- `documentId` корректно извлекается из URL
- При уходе со страницы появляется диалог подтверждения
- Существующие функции работают без регрессий
- Архитектура готова к подключению аутентификации

# 5. Аутентификация и авторизация

## Цель

Подключить полноценную систему:

- регистрации
- входа
- авторизации

и перейти с mock-пользователя на реальную аутентификацию.

## Функциональные требования

### Регистрация

Поля:

- имя
- email
- пароль
- подтверждение пароля

### Вход

Поля:

- email
- пароль

### Валидация

- корректный email
- пароль ≥ `8` символов
- совпадение паролей

### Токены

После успешного входа:

- JWT Access Token
- Refresh Token

### Хранение токенов

- Access Token:
  - in-memory

- Refresh Token:
  - `httpOnly cookie`
  - или `localStorage`
  - с обоснованием выбора

### Дополнительные требования

- Автоматическое обновление Access Token
- Logout:
  - очистка токенов
  - redirect → `/login`

- Защищённые маршруты:
  - `/dashboard`
  - `/documents/:documentId`
  - `/profile`

- Пользователь видит только свои документы
- API фильтрует документы по `userId`
- При доступе к чужому документу:
  - `403`
  - redirect → `/dashboard`

## Критерии приёма

- Регистрация и вход работают корректно
- Неавторизованный пользователь перенаправляется на `/login`
- После логина пользователь возвращается на исходный маршрут
- Пользователь видит только свои документы
- Попытка открыть чужой документ вызывает `403`
